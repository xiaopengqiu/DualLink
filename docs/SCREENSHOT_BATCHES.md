# 手动触发多图整题回答（1.5.0）

## 使用

1. 全屏截图默认 **Ctrl+Alt+S**，框选截图默认 **Ctrl+Alt+R**。两者只把图片存到本机「本题待回答截图」，不会自动上传或调用模型。
2. 题目较长时，按阅读顺序继续截图。题干、选项、代码可以分别截图；有重叠也可以。每题最多20张，单张12MiB，合计96MiB。
3. 在缓存列表可以预览、移除误截图片，或者清空本题。
4. 确认题目截全后，按 **Ctrl+Alt+Enter**，或点击「回答这道题」。当前缓存会固定成一批，逐张上传成功后创建**一个回答任务**。
5. iPad查看这批全部截图和一份整体回答。生成期间新截的图片进入下一题，再次触发才会提交。

快捷键可在「偏好设置」修改。通用回答快捷键在有待答截图时优先提交截图；没有待答截图时，继续触发进行中语音会话的回答。语音页的「回答当前问题」按钮始终只提交语音问题。若误截影响了语音快捷键，先移除/清空截图即可。

模型及执行方式在触发时确定。管理员可使用网页中的截图默认配置，或关闭「截图使用账号默认模型」后使用本机独立配置；普通账号继承管理员统一配置。已提交批次不会因后来更换模型而改变。回答风格和知识库由服务端在创建任务时保存快照。

## 缓存、排队和重试

- 未触发的图片只保存在PC当前用户的应用数据目录，不进入云端或AI。退出后重新打开仍可继续，不需要为了升级而提交待答缓存。
- 多次触发代表多道题，各批次保留自己的截图顺序和模型。客户端按提交顺序上传，服务端按任务队列处理。
- 上传失败保留整批图片，自动退避重试，也可点击「重试上传」。一批没有成功时，后续批次等待，避免题目顺序混乱。
- 单张图片用稳定截图编号去重；整题用稳定requestId去重。即使网络在云端已经创建回答后断开，恢复或重启也会找回同一个任务，不会因此重复创建回答或扣应用任务额度。
- 已提交批次不能再移除单张图片；需要修改时，在网页重新组织截图并明确发起新任务。回答失败可在网页点击重试，沿用整题截图和原配置。
- 本机图片直到云端确认接收整题任务后才清理。解除配对或云端撤销设备会清除该设备本机缓存，避免混入其他账号。

同网直传仍可开启，但只在**触发后**传输。iPad收到图片并成功上传云端后回复包含云端截图ID的确认；直传失败时PC回退云端。iPad未打开也能提交，之后打开网站可以查看历史回答。

网页手动上传支持一次选多张，默认只上传并加入当前题目，点击回答才调用模型；「再次分析」会使用该题完整图片顺序。图片由模型按顺序综合理解，不生成可能缩小文字的长拼接图。

## AI如何理解多图

系统提示词会说明：

> 本次截图均属于同一道题，按截图顺序提供。先综合所有截图还原完整题意、条件和代码，识别并去除滚动截图中的重叠内容，再给出一个完整回答，不逐张分别作答。缺页、冲突或看不清时明确指出。

Codex会收到多个图片参数；Claude会收到同一条用户消息中的多个图片块。长知识库需要先提取检索词时，提取阶段同样读取全部截图；因此可能有一次额外检索调用，但只生成一个整体答案。

## 从1.4.x升级

**先升级Linux服务端，再升级Windows客户端。** 此版本需要新的多图API和数据库表，不需要增加百炼或CLI配置。

在服务器已有Git源码目录操作（下面假定为 `/opt/dual-link-src/DualLink`，请换成你实际保存源码的位置）：

```bash
cd /opt/dual-link-src/DualLink
sudo git fetch origin --tags
sudo git checkout v1.5.0
sudo systemctl stop dual-link
sudo install -d -m 700 /var/backups/dual-link
sudo tar -czf "/var/backups/dual-link/before-1.5.0-$(date +%Y%m%d-%H%M%S).tar.gz" \
  /etc/dual-link.env /var/lib/dual-link/data
sudo env PATH=/usr/local/bin:/usr/bin:/bin:/usr/local/sbin:/usr/sbin:/sbin \
  bash deploy/install.sh http://47.102.103.66:3000 native
sudo systemctl restart dual-link
sudo systemctl status dual-link --no-pager
curl -fsS http://127.0.0.1:3000/api/health
```

若实际使用3001端口，将安装命令和健康检查里的3000换成3001，并保持 `/etc/dual-link.env` 的PORT/PUBLIC_ORIGIN与原来一致。安装脚本保留已有环境文件，不自动改端口、已有认证或百炼Key。若不是Git源码部署，可以从发布页下载1.5.0源码包解压后执行相同的安装步骤。备份应在停止服务之后进行，以完整保留SQLite/WAL与资料；安装失败先查看日志再恢复服务。

健康检查应显示 `version: "1.5.0"`。然后在PC「偏好设置 → 客户端更新」点击「一键升级」，或从GitHub发布页手动安装1.5.0，最后刷新iPad网页。

1.4.x遗留的尚未上传截图会迁移为手动待答缓存，不自动分析。已在旧版本上传或创建的云端任务保持原历史记录。新客户端连接旧服务端时会保留截图并提示更新服务端，不会把整题降级为逐张自动回答。

Root owns native-audio-providers.mjs and its tests/fixtures, root docs/e2e/package/lock/release. Server agent owns remaining apps/server/**. Desktop owns apps/desktop/**. Web owns apps/web/**. Do not commit until root integration, do not alter other owners' files. Existing HTTP+IP support remains.

## Data/API
Interview gains `mode:'transcript'|'audio'` (default transcript), `transcribe:boolean` (audio background ASR default true; transcript always true), `audioModel:string`, `audioWindowSeconds:number` (15..180, default120). Existing `provider:codex|claude|bailian` is text provider; actual Answer gains `mode` and audio answers use provider `omni` in answer only. New sessions default `autoAnswer:false`; audio always manual. Legacy transcript autoAnswer may remain explicitly selectable. Mode change only while paused/ended to avoid ambiguous live pipeline changes; cancel active answer on settings changes.

GET /interviews/config existing fields plus `audioConfigured:boolean,audioModels:string[],defaults:{mode,provider,transcribe,audioModel,audioWindowSeconds}`. `configured` remains ASR availability for compatibility. Account defaults persisted tenant-owned. GET /interviews/preferences -> `{preferences:defaults}`; PATCH /interviews/preferences accepts same defaults fields and returns `{preferences}`. Web authenticated account config; paired device may GET and use defaults but PATCH preferences browser only. No secrets to clients. Defaults from INTERVIEW_DEFAULT_MODE=transcript, OMNI_MODEL=qwen3.8-omni-flash-realtime, OMNI_MODELS comma list, INTERVIEW_AUDIO_WINDOW_SECONDS=120.

POST /interviews body supports new fields; GET/detail/export/events include them. Recording mode requirements: transcript needs ASR configured, audio needs audioConfigured, optional audio background transcribe failures do not block raw recording/native answers. If audio transcribe false no ASR tasks or quota charges. UI labels unavailable configuration accurately.

POST /interviews/:id/trigger `{requestId:UUID}` -> `{question,answer}`. Same requestId idempotent; short duplicate triggers (<600ms) coalesced server/client; new trigger cancels stale running answer. Device must own and be assigned recorder; browser owner may trigger. Default Ctrl+Alt+Enter customizable, conflicts with screenshot shortcuts rejected. Trigger works while recording or paused; no current session/audio/transcript gives actionable error. During recording desktop flushes Worklet pending PCM (without stopping graph), awaits complete in-flight writes+sends and all ACKs for sent frames before POST trigger. Offline keeps PCM, trigger reports wait reconnect instead of answering stale input. Server uses accepted frame watermark. Transcript trigger waits bounded ~1200ms for remote final, can use latest partial snapshot explicitly labelled; native audio never waits ASR. No automatic generation based on voice silence for manual mode.

Current question: remote material since previous trigger watermark up to now, bounded by configured lookback, plus consecutive utterances. If no new remote audio/text regenerate last question (new answer), using original captured question metadata. Candidate self audio only history. A question retains immutable audio range/watermark and mode/model on answer submission; late transcripts may not silently cancel manual snapshot. Audio question text may be `音频提问 mm:ss–mm:ss` (not fabricated transcription), audioRange `{startMs,endMs}` and `audioTruncated:boolean` exposed. Show explicit truncation when window omits earlier audio. Do not use replayed historical frames as fresh question triggers.

## Native runner (root)
createNativeAudioRunner(options={}) -> async run({prompt,audioTurns:[{track:'remote'|'self',startMs,endMs,pcm:Buffer,currentQuestion?:boolean}],model?,signal,onDelta}) -> `{answer,usage?}`. options `{apiKey,workspaceId,region,wsUrl,model,models,timeoutMs,startTimeoutMs,maxAudioBytes}` map to OMNI_API_KEY fallback DASHSCOPE_API_KEY, OMNI_WORKSPACE_ID fallback DASHSCOPE_WORKSPACE_ID, OMNI_REGION fallback ASR_REGION, OMNI_WS_URL override, OMNI_MODEL. Export nativeAudioConfiguration(options) returns config including configured/model/models (API only expose nonsensitive). Inject `options.audioRunner` / `options.omni` via createApp into interview service for tests. Root native runner no jobDir requirement, no CLI, no ASR dependency. Fresh Qwen manual session per answer: set text-only output, disable input transcription and auto replies; label each source audio turn; include explicit server prompt/KB/history, generate only after audio commits. Return only answer text, ignore reasoning/audio/tool logs, bounded queues/output/start/finish/inference, AbortSignal/close cleanup and safe errors. Audio mode fails explicitly on missing key/permission, never silently falls back to ASR/text.

## Storage/history
Persist private PCM working recording even AUDIO_RETENTION_DAYS=0 while non-ended, to support direct answers and mode choice. Zero means delete raw working files on end (after outstanding audio jobs settle) and cleanup old inactive sessions; full text/history independent. Retained PCM quota applies and explicit gaps remain. Read selected PCM by ledger offsets/timestamps with bounded ranges/bytes; preserve remote/self separately, no raw mixing or AI suggestions as actual speech. Native input = server style/KB/recent actual transcripts+earlier relevant actual excerpts, plus recent separately labelled self/remote audio context and current remote question. With background transcription disabled, disclose earlier audio beyond current bounded working context may not be included, full audio remains archived per policy. All question/answer/context metadata exported; UI offers retained remote/self audio access and distinguishes no transcript vs empty recording. AI suggestions never included as factual history or native prior assistant context.

# 按场景配置执行方式和模型

模型配置由管理员统一维护，截图、转写问答、语音识别和直接音频问答各自独立。管理员在网页「账号设置 → 模型与接口配置」填写模型 ID、API Key、接口地址及百炼业务空间、地域。普通用户和已配对客户端自动继承管理员配置，不能通过界面或 API 覆盖执行方式、模型或密钥。

| 场景或阶段 | 执行方式 | 配置内容 |
| --- | --- | --- |
| 截图回答 | Codex CLI / Claude CLI | 分别保存两个 CLI 对应的模型 ID |
| 语音转文字 | 百炼 Token Plan HTTP 分段 / 流式 ASR API | 识别模型 ID |
| 基于转写文字回答 | Codex CLI / Claude CLI / 百炼文本 API | 分别保存每种执行方式的文字模型 ID |
| 直接音频回答 | 百炼 Qwen-Omni API | 音频模型 ID、问题回看范围 |
| 直接音频的后台文字留档 | 百炼 Token Plan HTTP 分段 / 流式 ASR API | 识别模型 ID、后台转写开关 |

Codex / Claude 是执行工具的名称，不代表实际模型。Claude 接入百炼兼容接口时，应填写该接口支持的百炼模型 ID，而不是照抄 Anthropic 模型名称。Codex 的模型 ID 也取决于它在服务器实际连接的供应商。

## 在网页中设置

管理员可在账号设置统一保存截图和文字回答的默认执行方式及各模式凭据，也可在截图配置中修改截图默认模型。Codex 和 Claude 的模型字段分别保留；切换执行方式不会把一种模型名复制给另一种。留空表示使用服务器配置或 CLI 默认模型。管理员的单次截图分析也可以显式指定执行方式及模型，普通用户始终使用管理员默认值；已经提交的任务保存自身配置，不会被后续默认值修改。

管理员在「面试会话 → 默认面试配置」设置转写模型、文字回答执行方式及对应模型、直接音频模型。新建面试时可以覆盖本场配置。开始录音后，先暂停，再修改本场配置并继续；旧回答和记录保留原配置快照。

例如，截图阶段可以使用自己已开通、支持图片输入的高质量模型；转写后的文字回答可以使用同一接口支持的 Flash 模型。直接音频阶段必须选择支持当前 Qwen-Omni Realtime 协议的模型，不能把纯文本 Flash 模型填入音频字段。

语音识别方式可以在管理员账号设置中选择「自动」「Token Plan · HTTP 分段识别」或「实时识别 · WebSocket」。自动模式会根据非实时模型名或 Token Plan Key 选择 HTTP；普通流式模型继续使用 WebSocket。Token Plan 使用 `qwen-audio-3.0-asr-flash`，无需业务空间 ID。HTTP 分段默认最长 4 秒，允许 2–15 秒，短暂停顿会提前提交，纯静音不会发送模型请求。模型 ID 输入框允许自定义名称，不表示任意模型或接口协议都可以运行；供应商仍会检查模型可用性、权限和额度。若服务器设置了模型允许列表，只能选择列表中的模型。

Token Plan 的语音识别接口可填 `https://token-plan.cn-beijing.maas.aliyuncs.com`，也可留空自动生成。历史上填写的 `/compatible-mode/v1` 会在 HTTP 分段模式下自动改用 `/api/v1/services/aigc/multimodal-generation/generation`。音频用 WAV Base64 直接提交，不需要公开音频 URL。每路录音独立排队、按顺序保存字幕；短暂的网络异常、429 或 5xx 最多重试一次，积压或识别失败会明确记录缺口，并保留已接收录音用于补传。

点击「回答当前问题」或按客户端回答快捷键会先提交当前尾段，再使用识别文字生成答案；暂停、结束和正常断线也会尝试保存尾段。分段识别的字幕有片段采集时间和接口处理延迟，不能视为逐字实时转写。

Claude 可选择标准 API Key（`x-api-key`）或兼容供应商的 Bearer Token（`Authorization`）认证。使用百炼等兼容接口时，根据供应商的 Claude 接入方式选择 Bearer Token。语音接口地址可留空自动生成；普通 WebSocket 模式自定义时填写完整 HTTPS 地址，包含 `/api-ws/v1/inference` 或 `/api-ws/v1/realtime` 路径，服务器会使用 WSS 连接；Token Plan 分段识别使用上述 HTTP 接口。

### 密钥保存与生效范围

只有网站管理员可读取配置状态和修改配置；普通用户只取得运行所需的模型默认值，不会取得密钥或接口凭据。API Key 保存后不回显，输入框留空保留已存密钥，点击清除并保存后回退到服务器认证。其他字段留空使用服务器默认设置，CLI 可继续复用服务账号已有登录状态。

网页保存的配置使用 AES-256-GCM 加密存放在数据库中，加密密钥位于 `DATA_DIR/.ai-settings.key`（权限 0600）。备份和恢复必须同时保留数据库及这个密钥文件；现有的完整数据目录备份包含两者。不要把它们加入源码或发布包。

网页是管理员默认配置的权威来源。保存后，新截图、新文字回答以及已有会话的后续回答都会读取最新默认值，不再被会话创建时复制的旧默认值或客户端缓存覆盖。只有管理员在网站显式设置的本场覆盖优先于管理员默认值；清空该字段可恢复继承。旧版本会话复制的字段不再当作本场显式覆盖。已排队、运行或完成的任务保留提交时的模型快照。凭据用于后续新调用或新连接；已建立的语音识别连接需暂停再继续，才会使用新识别配置。

## PC 客户端

「偏好设置 → 截图使用账号默认模型」默认开启。PC 截图时读取账号的截图配置，随后把执行方式和模型存入本机上传队列。断网时优先使用本次连接已缓存的账号配置；尚未取得账号配置时使用本机默认配置。待传截图保留捕获时选定的配置，不会在重试时跟随新配置变化。

关闭「截图使用账号默认模型」后，可以在 PC 分别填写本机截图用的 Codex、Claude 模型 ID，并选择执行方式。这只影响本机截图，不会修改账号默认值或面试模型。

「面试录音」读取账号默认配置，也可在开始前设置本场的文字模型、转写模型或音频模型。已开始的会话请在网页暂停后修改本场配置，PC 会同步会话状态。默认 `Ctrl+Alt+Enter` 触发回答，可在偏好设置修改；不会因模型配置而自动开启回答。

## 复用服务器 CLI 与百炼认证

终端中的 `claude --model 实际模型ID -p "测试问题"` 可用于验证该 CLI 的模型选择。DualLink 会把任务选择的模型作为 `--model` 参数传给对应 CLI；Codex 面试热进程使用本次请求的模型启动独立模型线程。

Claude 使用百炼等兼容供应商时，服务端需要取得同一套 `ANTHROPIC_BASE_URL` 和 `ANTHROPIC_AUTH_TOKEN`，或供应商接受的 `ANTHROPIC_API_KEY`。可同时设置 `ANTHROPIC_MODEL` 和 `ANTHROPIC_DEFAULT_HAIKU_MODEL` / `SONNET` / `OPUS` 映射；网页账号或会话选择的模型会以 `--model` 覆盖这些默认值。也可以在管理员账号设置中为截图和转写问答分别填写；网页配置优先于服务器环境。`admin` 用户已有配置不会自动进入以 `duallink` 用户运行的服务。

需要加载既有 Claude 用户配置时，由管理员设置 `CLAUDE_LOAD_USER_CONFIG=true`，并让 `CLAUDE_CONFIG_DIR` 指向服务用户可访问的专用配置目录。默认关闭用户配置和所有项目设置；开启前应检查其中的配置。只复制必要文件，不要挂载完整个人家目录、不要放宽 `ProtectHome`。服务不会传递 `CLAUDE_CODE_SUBAGENT_MODEL`，并始终关闭问答任务的工具和 MCP、禁用会话持久化、启用安全模式。需要加载自定义 Codex 提供方时，设置 `CODEX_LOAD_USER_CONFIG=true`，并准备服务用户可访问的 `CODEX_HOME`。

例如，现有百炼接口和 Key 已保存在 `/home/admin/.claude/settings.json` 时，可复用这一份配置，无需重新申请 Key 或登录 Anthropic：

```bash
sudo install -o duallink -g duallink -m 600 \
  /home/admin/.claude/settings.json \
  /var/lib/dual-link/.claude/settings.json
sudoedit /etc/dual-link.env
```

环境文件中设置 `CLAUDE_LOAD_USER_CONFIG=true`，保留 `CLAUDE_CONFIG_DIR=/var/lib/dual-link/.claude`。复制前确认实际家目录与配置路径；后续修改 admin 配置不会自动同步到副本。若原先通过 `.bashrc` 导出认证变量，则应把所需变量写进服务环境文件；不要把包含 Key 的配置提交到仓库。

修改 `/etc/dual-link.env` 后重启：

```bash
sudo systemctl restart dual-link
sudo journalctl -u dual-link -n 100 --no-pager
```

音频模式独立使用百炼 API，不能继承 Claude / Codex 的文字模型能力。百炼 ASR 和 Omni 的 Key、业务空间和地域可以在管理员账号设置中分别配置，留空则使用服务环境文件。CLI 文字接口可用不代表该 Key 同时具备音频模型权限。

## 验收

1. 管理员给截图的 Codex、Claude 分别填写不同模型 ID，切换执行方式并重新打开网页，确认各自保留。
2. PC 保持使用账号默认模型，截图后检查任务记录中的执行方式和模型。修改账号默认后确认旧任务配置不变。
3. 为转写问答填写单独的 ASR 和快速文字模型，开始录音，确认字幕可用且按键后才生成回答。
4. 暂停会话并切换文字执行方式，继续录音，确认下一条回答使用新的配置。
5. 直接音频模式填写可用的 Omni 模型，先关闭后台转写验收，再开启验证字幕和留档。
6. 在真实供应商上比较「按快捷键到首个有用文字」的时间；模型名称包含 Flash 不保证固定延迟，服务器网络、问题长度、额度和模型负载都会影响结果。

管理员模型卡片显示“已保存的生效模型”和来源；会话显示实际用于后续请求的模型及“管理员网页配置 / 本场显式覆盖 / 服务器默认”来源。页面中的编辑草稿只有保存成功后才生效。截图与面试、语音识别与音频直答仍分别保存；留空才回退到服务器环境或 CLI 默认模型。

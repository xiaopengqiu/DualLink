# 历史记录与自动清理（1.6.0）

## 在哪里管理

在iPad或电脑网站打开侧栏「历史记录」，切换「截图历史」「语音历史」。普通账号也能管理自己的历史和保留设置，不需要管理员代为删除。

- 支持搜索、分页、单条删除、全选本页后批量删除。
- 「清空截图历史」「清空语音历史」覆盖所有页面，执行前显示确认；正在处理的记录会保留。
- 「查看」可回到截图/面试详情，即使记录不在最近100条中也能打开。
- 空间统计显示截图数、语音会话数、图片及原始音频的附件用量。
- 其他已打开设备会收到删除事件，清除对应预览、问答和浏览器草稿。

删除截图会同时删除引用该图片的整题回答；同题的其他图片仍可单独保留。删除语音会话会删除该场的转写、问题、AI回答、上下文快照、缺口记录和保留的原始音频。Prompt、知识库、账号和设备配对不属于历史，不受这些删除操作影响。

## 默认保留规则

| 设置 | 默认值 | 说明 |
|---|---:|---|
| 自动清理 | 开启 | 过期或超过限额时，从可清理的旧记录开始释放空间 |
| 历史保留天数 | **30天** | 可自行调整；截图按最近关联活动、语音按结束时间判断 |
| 截图数量 | 1000张 | 每个账号独立限制 |
| 语音会话数量 | 200场 | 每个账号独立限制 |
| 附件空间 | 1024MiB | 包括截图、原始音频和尚未实际删除的文件 |

在历史页修改并「保存清理设置」。保存后服务端会按新规则维护，缩短期限或降低上限可能删除旧记录；有需要保留的内容应提前导出或备份。「立即按规则清理」按照已保存的设置执行。关闭自动清理后，上限仍然有效，容量不足时停止新增，先手动删除或调整上限后再继续。

保留天数可设为1–3650天；截图1–5000张，语音1–2000场，附件1–102400MiB。为避免对同一截图反复回答造成数据库增长，另有每账号5000条截图回答历史上限，优先清理较旧且非最新的已完成回答。

原始录音仍受服务器独立的 `AUDIO_RETENTION_DAYS` 控制，原有默认是7天，可能先于30天问答历史过期。历史页显示这个期限；本次升级不会延长原始音频的保留时间。音频过期后，在历史期限内仍可查看和导出文字问答。

## 正在使用的内容

自动清理会跳过：正在排队/生成回答的截图、尚未结束的录音（含暂停）、尚在生成回答的语音会话，以及刚上传未组题的截图。

批量删除会保留活跃任务和未结束录音，并说明保留数量。可以先在详情结束会话、取消任务后再删除；已有详情页的单条删除入口保留明确确认后停止并删除的能力。刚上传但未分析的截图可以手动删除，不必等待自动清理保护期结束。

PC收到云端删除通知或明确的已删除响应时，会停止该批截图或语音的对应重传，并清理匹配的本机缓存；其它批次和未触发截图保留。网络/文件损坏仍走正常恢复流程。服务端保存有期限和数量上限的删除编号，避免重试把已经删除的历史重新传回。

## 磁盘是否释放

删除不只隐藏列表：数据库关系和附件会一起处理。临时文件占用或权限问题导致附件删除失败时，服务端把它记入持久化待删清单，后台及立即清理时继续重试，空间统计仍计入这些文件，不会假装空间已经释放。

SQLite删除的页面可以供后续记录复用，数据库文件大小不一定立即缩小；不在运行中自动执行全库VACUUM。默认天数、数量、附件限额及内部回答上限共同限制增长。备份、知识库、日志和客户端升级备份不是截图/语音历史，由各自的管理方式维护。

PC正常上传结束的录音缓存会立即移除；异常退出留下的已结束且完整确认缓存超过30天后清理。未上传完的录音、未触发截图不会因清理历史而按时间静默丢弃。未被本机队列引用的过期截图残留会定期清理。

## 升级已有阿里云部署

1. 先备份云端数据和 `/etc/dual-link.env`。
2. 拉取main或切换 `v1.6.0`，从源码目录运行原安装命令，再重启服务。admin用户、HTTP公网IP和已有CLI/百炼配置保持原配置，无需新增密钥。
3. 服务器首次启动就会按30天规则维护已有账号，过期历史会被删除。需要保留旧资料时应先导出或备份；之后调大保留天数不能恢复已经删除的记录。
4. PC客户端通过「偏好设置 → 客户端更新」升级至1.6.0，iPad刷新网页。

```bash
# 进入你实际保存Git源码的目录，再执行：
git pull --ff-only origin main
sudo systemctl stop dual-link
sudo install -d -m 700 /var/backups/dual-link
sudo tar -czf "/var/backups/dual-link/before-1.6.0-$(date +%Y%m%d-%H%M%S).tar.gz" \
  /etc/dual-link.env /var/lib/dual-link/data
sudo env PATH=/usr/local/bin:/usr/bin:/bin:/usr/local/sbin:/usr/sbin:/sbin \
  bash deploy/install.sh http://47.102.103.66:3000 native
sudo systemctl restart dual-link
curl -fsS http://127.0.0.1:3000/api/health
```

如果实际端口是3001，把上面两处3000替换为3001，并核对原环境文件中的PORT/PUBLIC_ORIGIN。健康检查应显示1.6.0。完整部署步骤见[部署指南](DEPLOYMENT.md)。
